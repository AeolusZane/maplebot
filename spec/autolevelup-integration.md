# AutoLevelUp 集成方案 v0.3

## 核心边界

保留原应用和 Interception 后端，把动作来源从固定录制路线扩展为模型。新代码是 AutoLevelUp 内的策略与录制模块，训练/评测 CLI 只是辅助工具。首版固定地图与角色，先跑通已有感知，再收集演示；不把完整平台模拟器或重新开发 GUI 作为首次录制的前置条件。

```text
GameWindowCapturor + 原定位/怪物识别
                  ↓
            ObservationBuilder
                  ↓
      策略模式路由（每次只启用一个）
       legacy          model
       原路线决策       本地/局域网推理
          └───── ActionProposal ─────┘
                         ↓
             原 KeyBoardController 改造
          校验、到期、去重、按键状态与回执
                         ↓
        原 InterceptionController key_down/key_up
                         ↓
                    游戏键盘输入
```

## 四种模式

| 模式 | 人操作 | 自动决策 | Interception 输出 |
|---|---|---|---|
| legacy | 可暂停接管 | 原路线/攻击策略 | 开启，用作可回归基线 |
| manual_record | 真人控制 | 仅感知与记录 | 禁止所有自动输出 |
| model_shadow | 真人控制或观察 | 模型提出动作并记录 | 禁止所有自动输出 |
| model_control | 停止键可随时接管 | 模型决策 | 本地控制器校验后执行 |

模式切换先停止生产新动作、取消 pending、释放程序持有键、增加 epoch、清空模型状态，再进入新模式。切换失败停在 STOP。manual_record/model_shadow 不初始化真实输出后端；在检测、自动登录/点击、药水、回城、Buff、拾取等所有旁路上施加同一个输出门禁。不能只调用旧 disable_control 就认为已经无输出。

演示录制与自动控制互斥，避免把合成键录成真人。原输入监听用于快捷键不等于完整演示采集，需单独实现目标窗口允许键的按下/释放捕获。换焦点或停止时缺失释放须标记为取消，不伪造真人动作。

## 决策与执行协议适配

模型使用 left/right/up/down/jump/attack 等语义键，按原配置解析 jump、directional_attack 或 aoe_skill 等具体键。配置在一次会话中冻结；变更键位需要新 epoch 和新的 action_schema。映射冲突需预检，不能一个物理键同时承担互斥动作。

持续按住由 KeyBoardController 对比期望集合与自身实际持有集合，仅在变化时调用 key_down/key_up。tap 由 event_id 调度一次，按设定时长释放；不能把旧 `cmd_action=attack` 长驻状态直接当成每帧新点击。旧 set_command 接口由 legacy adapter 兼容并记录行为差异。

沿用 Interception 发键不意味着照搬其随机时长：模型/演示回放动作必须显式提供时长，避免底层再次独立随机；旧默认随机仅留在明确的 legacy 基线配置中。驱动调用异常需回执 failed，成功回执仅代表调用完成，不代表游戏实际响应。

原按键线程中的自动拾取/Buff 首版在模型模式默认关闭；如需恢复，由独立辅助策略提交带 source 的动作请求。药水可作为显式开启的辅助策略，manual_record/shadow 中一律无输出。模型不认识的辅助键不强行纳入“十个键”，是否开启必须写进 manifest 并在评测分组中一致。

## 模型模式不允许旧路线接管正常动作

规则路线与模型不得同时改变 cmd_move_x/y/action。首版模型模式检测到卡住、不可达或未知地形时 STOP/提示人工处理；自动恢复作为后续显式配置功能，不暗中启用旧回正算法遮盖模型错误。legacy 继续保留原回正，回滚时取消旧 epoch 后切回 legacy。报告记录模型停止、人工接管和辅助策略介入次数。

地形首版可通过 F4 小地图底图加人工平台/梯子区域标注准备；旧路线图片不等于可达图。将地图版本、坐标转换与识别质量送给模型，必要字段缺失时暂停该场景实验。

## 最小用户流程

1. 在 Windows 用现有入口启动，完成原角色模板、怪物模板和地图准备，短时验证 legacy。
2. 新 UI 选择“演示录制”，查看观察是否有效，手动开始；正常操作后停止，检查配对数据。
3. 辅助 CLI 构建数据集、训练并导出模型包，可在另一台机器完成。
4. 同一 UI 选择“模型观察”，加载本地模型或局域网地址，核对提案和观测。
5. 输入链路在测试窗口验证后选择“模型控制”，仍经原 Interception 执行。
6. 失败时停止、导出片段并补录；不直接对测试集反复调参。

验收必须证明：四种模式的输出边界、原键位配置兼容、录制/控制互斥、无旧路线覆盖、无后台重复发键、显式时长不被二次随机、释放失败可见。
