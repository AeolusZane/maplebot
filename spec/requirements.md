# 需求规格 v0.2

## 背景与目标

用户在 Mac 上完成设计，随后创建代码库，在 Windows 开发、运行和测试。现有参考工程为 MapleStoryAutoLevelUp-CN 与 maplebot；新项目用于授权测试环境中的行为生成与检测评测。当前交付仅为文档，不修改参考仓库、不安装驱动、不执行游戏操作。

目标闭环：实时把人物、怪物、地形、可观测技能状态以及近期操作历史送给策略，策略直接提出少量允许键的组合与有效时长，本机校验、执行并反馈结果。先实现规则动作策略建立闭环，再用真人“观察—动作”配对数据训练行为克隆模型。候选为小型 GRU 序列模型，同时保留不使用历史的 MLP 对照；最终选择依据验证集表现和实机延迟。半马尔可夫策略降为可选高层意图模块，不再是必经交付。

首张场景预计常用键不超过 10 个，实际按键表由职业配置声明。模型输出受约束的多键集合，不把每个键当作互斥类别。静态地形按 map_version 提供，动态观察持续更新；录制路线作为规则基线与可选高层导航资源。正式动作模型模式下，旧路线执行器不得再覆盖模型提出的正常走位。

## 使用流程

录制员：预检 → 选择目标窗口及允许按键 → 显式录制 → 正常操作 → 停止 → 检查同步/缺失 → 回看并标注 → 纳入数据集。

开发者：核心测试 → 模拟基线 → 生成器 → 留出数据评测 → Windows shadow 观察模式 → 测试窗口执行 → 授权环境短时闭环。

CLI 优先；首版只需要录制状态提示、停止入口和回放标注能力，不要求重写现有 GUI。所有执行模式必须显示当前模式，默认 `trace`，真实输出需明确选择适配器。

## 约束与非目标

- 1GB 显存不是性能保证；核心不依赖 GPU，游戏、抓帧、模板识别是否可用须实测。
- 不承诺通过某个线上反作弊系统，不实现驱动隐藏、挑战绕过或以封号结果为优化反馈。
- 不在首版实现多账号调度、大模型实时控制、强化学习或跨地图自主探索。
- 不把源码注释中的历史帧率当作当前设备测量值。
- 现有地图路线只充当导航资源，不能自动推导完整地图可达图；第一张测试图的区域、连接与失效条件需人工确认。

## 共用验收门槛

- 所有 R01–R16 有测试或人工证据，并在报告中标明通过/失败/未运行；两机部署暂缺硬件时 R14 标记未运行，不声称完成远端验收。
- 无重复一次性动作、无失效命令继续执行、停止后无未释放的受控键。
- 数据不可用与角色死亡等未知状态不得伪装成正常观察。
- 各平台运行记录包含 commit、依赖锁、配置摘要、随机种子、样本清单。
- 性能阈值见 Windows 手册，均为待验证的工程目标；拟真指标见评测方案，不预设“极其真人”的成功结论。
