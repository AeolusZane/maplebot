# Phase 6：Windows 集成与交接

上级：[requirements](../requirements.md)。依赖：Phase 1–5 工程交付；拟真证据不足需保留。落实 R11、R12，可选 R14。

## 实现

- doctor 预检、Windows 可选依赖锁、配置样例、测试窗口执行器。
- 感知适配器输出带质量和时效的快照；接入已有路线时锁定参考版本。
- 执行所有直接输出收口审计，再开启 shadow 和测试窗口 execute。
- 按 [Windows 手册](../windows-validation.md) 完成故障矩阵、性能测量与证据打包。
- 用户提供实际硬件和地图配置，填写 manifest；结果反馈不包含不必要的私人输入。

## 验收

- [ ] 新 Windows 环境按文档能安装、运行 doctor、通过核心测试。
- [ ] shadow 模式零真实输出；execute 仅作用于明确选择的测试目标。
- [ ] 急停、失焦、捕获失效、异常、退出均验证释放流程。
- [ ] 10 分钟样本报告阶段耗时与资源占用，1GB 显存设备是否可用以报告为准。
- [ ] 至少一轮完整采集→校验→回放→模拟生成→评测→报告可重现。
- [ ] 形成 passed/failed/not_run 清单与未解决问题，更新 README 的已实现能力。

## 可选局域网扩展

仅当本地闭环通过后开发 RemotePolicyClient/服务端，沿用 Intent 协议。认证、请求关联、epoch、消息限额、期限检查与断线停止必须一起交付。

验收：延迟、乱序、重复响应、断网、服务重启、会话串线均不能执行旧意图；跨机单调时钟不直接比较。记录网络 RTT 与整个观察到动作延迟。扩展失败不影响本地方案交付。
