# Phase 3：离线环境与规则基线

上级：[requirements](../requirements.md)。依赖：Phase 1；Phase 2 数据可后接。落实 R07、R08、R11。

## 实现

- 单张合成地图：平台、可达连接、怪物、掉落/受击事件；定义有限物理规则与观察范围。
- DeterministicPolicy 与 TimingJitterPolicy；配置可冻结。
- 两种基线均输出 ActionProposal，与模型共享动作表和调度器；旧路线导航仅供规则基线使用。验证模型直接组合键提案可驱动模拟器，提案和过滤结果可关联。
- 仲裁器、单所有者按键调度、动作去重、期限和执行回执。
- 注入观察丢失/迟到/目标消失，验证停止与恢复。
- 参考代码仅通过适配器提出候选动作，全部输出进入 TraceSink 或模拟器。

## 验收

- [ ] 同一外部事件种子下两种基线完成实验并输出可比较轨迹。
- [ ] 同 action_id 的 tap 最多执行一次；移动按键生命周期闭合。
- [ ] 失效命令、观察过期、异常时停止；无直接输出旁路。
- [ ] 模拟器真值只进入评测，策略只能获得允许观察。
- [ ] 时间扰动不产生非法键组合或突破硬冷却。

证据：闭环模拟报告、故障测试、基线配置摘要。范围外：Windows 真实输入、真人拟真结论。

## v0.3 执行复用与验收（R17、R18）

原 KeyBoardController 接入结构化动作，保持唯一输出线程。真实后端复用 InterceptionController，测试使用 spy/Trace。将 update_cmd_by_mob_detection 的识别与攻击决策分离，模型复用感知而不调用旧决策。legacy 保留原路线行为并记录适配差异。

验收：原键位配置正确映射；相同 held 状态不重复 key_down；tap 去重；四模式动作来源互斥，切换取消 pending、释放并更新 epoch。最小合成场景与录制帧足够做初期测试，完整地图物理仿真不作为首次录制前置。

## v0.4 日志断言与模拟闭环 G1/G2（R19–R21）

按 [离线规格](../offline-validation.md) 实现 O01–O13 的可控场景、自动断言、失败事件索引和 verify CLI。规则策略用 golden trace，模拟动作真实改变模拟位置/目标状态；不能只播放固定截图充当闭环。必测包括持有/释放、重复 tap、观测过期、异常、模式切换、平台/梯子和网络 stub 故障。输出 report.json、report.md、events.jsonl 与版本摘要，必测全通过才签收。
