# Phase 5：真人校准与检测评测

上级：[requirements](../requirements.md)。依赖：Phase 2、4。落实 R10。

## 实现

- 落实 [评测方案](../evaluation.md)：完整会话分组划分、冻结测试集、参数拟合与版本化。
- 提取驻留、转移、条件响应、序列相关与路线特征，质量不够的区间排除并记录原因。
- 实现 B0/B1/MLP/GRU 与历史、地形、时长消融；提供真人内部差异参照。硬约束不因消融关闭。
- 落实 R16，分别报告按键预测、闭环任务完成、行为相似、检测提升和提案修改/拒绝比例。
- 基线检测器与后续增强版分开训练，生成独立测试报告；特征中排除来源标签。
- 结果区分工程通过、拟真证据不足、拟真支持、检测提升支持。

## 验收

- [ ] 同 session 不跨数据集；训练、验证、测试清单固定且可追溯。
- [ ] 所有拟合参数有样本来源，缺数据状态标为未校准。
- [ ] 指标有样本量、分组与不确定性；无数据泄漏。
- [ ] 改进检测器在冻结测试集上评估，未用测试分数调生成器。
- [ ] 缺少样本仍能生成说明缺口的报告，不输出虚构百分比或通过结论。

证据：dataset manifest、split、模型摘要、报告与失败片段索引。研究门槛未达时允许进入 Phase 6 工程验证，但总需求的拟真项保持未验收。

## v0.3 数据归属

旧 F4 资源、纯真人演示和自动执行轨迹分开。比较组使用一致辅助药水/Buff/拾取设置。报告人工接管、模型停止与规则介入次数，不将规则救场算作模型成功；原 Interception 执行耗时作为闭环延迟的一部分。
